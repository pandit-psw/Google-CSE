# Quick Start Guide

## Local Testing (5 minutes)

### 1. Install Dependencies

```bash
npm install
```

### 2. Generate Master KEK

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Copy the output (it will look like: `xK8j9L2m5N3p7Q4r6S8t1U9v2W4x7Y0z...`)

### 3. Create .env File

```bash
cp .env.example .env
```

Edit `.env` and set:
```bash
MASTER_KEK_BASE64=<paste-the-generated-key-here>
ALLOWED_WORKSPACE_DOMAIN=yourdomain.com  # Your Google Workspace domain
```

### 4. Run Tests

```bash
node test.js
```

You should see:
```
✅ All tests passed!
```

### 5. Start the Server

```bash
npm start
```

You should see:
```
🔐 Google Workspace CSE Key Service
   Server running on port 3000
   Environment: development
```

### 6. Test the API

In another terminal:

```bash
# Health check
curl http://localhost:3000/healthz

# Test wrap operation (dev mode)
curl -X POST http://localhost:3000/v1/wrappedKeys:wrap \
  -H "Content-Type: application/json" \
  -H "X-Dev-User-Email: test@yourdomain.com" \
  -d '{
    "key": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=",
    "authentication": {
      "email": "test@yourdomain.com"
    },
    "reason": "ENCRYPT_DOCUMENT"
  }'
```

Expected response:
```json
{
  "wrappedKey": "base64-encoded-string...",
  "keyId": "kek_default_v1",
  "timestamp": "2024-..."
}
```

## Key Concepts

### How It Works

1. **User encrypts a document** in Google Docs/Drive
2. **Google generates a DEK** (Data Encryption Key) to encrypt the content
3. **Google calls your `/wrap` endpoint** to wrap (encrypt) the DEK
4. **Your service wraps the DEK** with your KEK (Key Encryption Key)
5. **Wrapped DEK is stored** with the encrypted content
6. **When opening the document**, Google calls `/unwrap` to get the DEK
7. **Your service unwraps the DEK** and returns it
8. **Google decrypts the content** with the DEK

### Security Model

- **DEK**: Generated by Google, encrypts the actual document content
- **KEK**: Generated and stored by YOU, encrypts the DEK
- **Master KEK**: Your root encryption key, must be kept extremely secure

Google never has access to your KEK, so they cannot decrypt your wrapped DEKs.

### Development vs Production

**Development Mode** (NODE_ENV=development):
- Simplified authentication (accepts email in header)
- Useful for local testing
- ⚠️ NEVER use in production

**Production Mode** (NODE_ENV=production):
- Full OAuth 2.0 authentication
- Verifies Google Workspace tokens
- Domain restrictions enforced
- Required for actual deployment

## FAQ

### Q: Is this really free?
A: Yes! Oracle Always Free tier + Google Cloud free tier = $0/month

### Q: Will Oracle VM be powerful enough?
A: Absolutely. Key wrapping is very fast (< 1ms per operation). The 4-core ARM CPU can handle thousands of operations per second.

### Q: What if I exceed Oracle Free tier limits?
A: Almost impossible for personal/small team use. The free tier includes:
- 4 ARM CPUs (plenty for this workload)
- 10 TB outbound traffic/month (each wrap/unwrap is < 1KB)
- No time limit (free forever)

### Q: Do I need a domain name?
A: Yes, for production. You need HTTPS with a valid SSL certificate for Google Workspace to trust your service. Domain names cost ~$10-15/year.

### Q: Can I use Cloudflare Workers instead?
A: Potentially, but there are challenges:
- Need persistent storage for KEKs (Cloudflare KV or Durable Objects)
- More complex authentication setup
- Cold start latency
Oracle VM is simpler and more reliable for this use case.

### Q: How secure is this?
A: Very secure IF:
- ✅ You keep your Master KEK secret
- ✅ You use strong authentication in production
- ✅ You keep your Oracle VM updated
- ✅ You restrict SSH access
- ✅ You backup your KEK securely offline
- ✅ You monitor audit logs

### Q: What happens if I lose my KEK?
A: ⚠️ All wrapped keys become unrecoverable. Your encrypted documents cannot be decrypted. **BACKUP YOUR KEK SECURELY!**

### Q: Can I use Firebase instead of Oracle VM?
A: Yes! You could deploy this to:
- Firebase Cloud Functions
- Google Cloud Run
- Google Compute Engine

But these aren't free (though very cheap). Oracle Always Free is truly free forever.
